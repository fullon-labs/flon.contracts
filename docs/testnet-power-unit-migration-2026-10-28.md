# Testnet governance power unit migration

This is a one-time migration of the existing testnet `dao.gov` tables. The mainnet contract has no legacy action or GLON-specific branch. Mainnet initializes `dao.gov` with `8,POWER` and never creates the old token.

The migration was executed on 2026-10-29 on the specified testnet. The temporary DAO contract was replaced by the clean production build. The temporary migration source in `scripts/` is retained only as an audit record and is excluded from the contract build.

## State and safety gates

- Chain ID must be `18b4d5837d83a8f7203ea57cb7ab37b9cef59547ea307e70b1bf1103cb06043f` at every transaction.
- Use only `https://t4.flon.network` and the local `fuwal`/`flontest` wallet. Never export private keys.
- The DAO global symbol must be `8,GLON`. All proposals must be terminal. An approved signal proposal is terminal for this migration; an approved executable proposal must first execute or expire.
- Capture `global`, `config`, `powers`, every voter checkpoint scope, `riskconfigs`, `policysnaps`, `proposals`, and every proposal endorsement and ballot scope. Verify total power equals the sum of voter power.
- Testnet backup from 2026-10-28 is in the DApp E2E evidence directory, `governance-power-before-20261028`: four voters, three proposals, total 10,799.

## Deployment order

1. Deploy the temporary `dao.gov` build generated by `scripts/prepare-testnet-power-migration.py`. It retains `syncpower` only while the old system contract is running, accepts `POWER` input from the new system, and adds `migrateunit`.
2. Deploy the clean `flon.system` build. New stake changes write governance power directly; they no longer mint or burn the old token. The temporary DAO normalizes its `POWER` input to the current table unit until migration.
3. Recheck chain ID, wallet, all proposal statuses and power conservation. Call `dao.gov::migrateunit` with the DAO admin authority. This transaction relabels assets in all governance tables, preserving integer amounts and history, and disables legacy `syncpower` because the global unit changes.
4. Verify every table uses `POWER`, total amount and all proposal vote amounts are unchanged, and `total_power` still equals the sum of voter power. Verify the transaction is irreversible.
5. Deploy the clean production `dao.gov` build without `syncpower` or `migrateunit`. Verify the ABI lacks both actions. Run a small addvote/subvote and confirm direct `setpower` updates in the new unit.
6. Deploy the DApp after its governance power display and help text are verified. Retain the old testnet `flon.token` code while old GLON supply exists; do not deploy the clean token build over it before legacy balances are retired.

The three contract builds are produced on `xch` under `/home/richardchen/flon-contract-builds/codex-power-clean-20261028`. The DApp E2E evidence directory contains their WASM and ABI copies with SHA-256 checksums. No migration action is part of the production build.
